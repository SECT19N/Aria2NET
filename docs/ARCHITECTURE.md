# Architecture

## Projects
| Project | What it is |
|---|---|
| `Aria2NET.Core` | Plain .NET library, no UI. App paths, settings store, aria2 config, RPC client, engine (process owner), file logger. |
| `Aria2NET` | WinUI 3 app (unpackaged, self-contained). DI setup, window, pages, view models. |
| `Aria2NET.Tests` | xUnit. Unit tests plus integration tests that start the real `aria2c.exe` (skipped if it hasn't been fetched). |

Keep UI types out of `Aria2NET.Core` so the logic stays testable.

## Process model (0.1)
The app owns a hidden `aria2c.exe` child process.

- On launch `Aria2Engine` writes `%LocalAppData%\Aria2NET\engine\aria2.conf` with a random loopback port and a random secret, then starts `aria2c --conf-path=...`. The secret lives only in that file (not on the command line).
- RPC is JSON-RPC over HTTP on `127.0.0.1`. Readiness = `aria2.getVersion` answers.
- `stop-with-process=<our pid>` makes aria2 exit on its own if the app is killed.
- On close the window cancels the close, calls `saveSession` + `shutdown`, waits up to 5 s (then kills), and closes.
- On startup any stray `aria2c.exe` from our own tools folder is killed.
- Unexpected exit → state `Crashed`, shown as an error bar with "Restart engine". Automatic restart is planned for 0.4.

## Downloads data flow (0.2)
- `DownloadMonitor` (Core) ticks once per second and asks `Aria2RpcClient.PollAsync()`, which sends **one** `system.multicall` (`tellActive`, `tellWaiting`, `tellStopped`, `getGlobalStat`, each with the secret token inside the call and a `keys` filter).
- The snapshot is raised on a background thread. `DownloadsViewModel` hops to the UI thread and updates `DownloadRowViewModel`s **in place by GID** (no list rebuild, so no flicker and scroll is kept).
- The monitor reads `engine.Rpc` on every tick and only polls while the engine is `Running`, so engine restarts need no re-wiring. While the engine is down the list is cleared and Add is disabled.
- Adding: `UrlParser` validates pasted text, then `AddUriAsync` is called per URL with `dir` (and `out` for a single URL).
- Gotcha: passing a `string[]` as the only argument to a `params object?[]` method binds the array to `params` itself. Cast to `object` (see `tellActive`).

## Controlling downloads (0.3)
- **Where the rules live (Core, no UI):** `DownloadCapabilities` decides which action is allowed for a status (menus, command bar and shortcuts all read it), `Aria2Errors` maps aria2 error codes to text, `DownloadView` does filter + sort on plain `DownloadItem`s, and `DownloadOperations` is the one service that talks to aria2 for pause/resume/remove/retry/move/rename/limit. All of it is tested without WinUI; `DownloadOperations` is also tested against a real aria2c.
- **Batches:** acting on several rows sends one `system.multicall` (token inside each call). A fault in one entry is reported but does not stop the others.
- **Remove:** live downloads get `forceRemove`, then every removed GID gets `removeDownloadResult` so aria2 forgets it. "Remove from list" hides the rows immediately and only sends the RPC after 5 s (`Undo`); closing the window finalizes it first. "Remove and delete file" sends finished files to the Recycle Bin and deletes partial files (and their `.aria2` control file) outright.
- **List pipeline:** `Apply(snapshot)` → keep one `DownloadRowViewModel` per GID → `DownloadView.Apply` (filter, sort) → `SyncRows` moves/inserts/removes rows in place. Moving a row makes WinUI's ListView forget its selection (and it reports that *during* the move), so the view model captures the selection first, ignores selection events while syncing, and the page re-selects afterwards (`SelectionRestoreNeeded` / `FinishRestore`).
- **Force start:** aria2 cannot bypass `max-concurrent-downloads`; the item is moved to the front and the limit is raised by one until it leaves Active/Waiting (`DownloadOperations.OnSnapshot` puts it back).
- **Gotchas found by real aria2:** a resumed download sends `Range: bytes=N-M` (M present), a test server that only understands `bytes=N-` answers 200 and aria2 fails with "No URI available" (error 8). aria2 reports only the original URL after a redirect, and an existing complete file with the same name makes a new download "complete" at once (`continue=true`).

## Persistence (0.4)
- **Data folder** (`%LocalAppData%\Aria2NET`, or `ARIA2NET_DATA_DIR` if set): `settings.json`, `history.db`, `backups\`, `engine\` (conf + `aria2.session`), `logs\`, `aria2net.lock`.
- **Lock:** `DataFolderLock` holds `aria2net.lock` open with `FileShare.None` for the whole run, so a second copy or another Windows session of the same user cannot write the same folder. The OS drops it if the app dies. A refused second copy shows a message and exits (the `AppInstance` redirect in `Program.cs` handles the normal same-session case first).
- **History:** `Data/Database` opens SQLite (WAL, no connection pooling so the file can be moved/deleted), applies `Migrations.All` in order (`PRAGMA user_version`), copies the file to `backups\history-v<N>-*.db` (via `VACUUM INTO`, consistent in WAL mode) **before** any schema change, and to `backups\history-start-*.db` after every successful start (newest 5 kept). A corrupt file is moved to `history.db.corrupt-<time>` and replaced; a file with a newer `user_version` than the app knows switches History off and is left alone. Never edit a shipped migration; add a new one.
- **Recording:** `HistoryRecorder` receives each `PollSnapshot` and writes only rows whose status/name/path/size/error changed. Unfinished downloads that vanish from aria2 are marked `removed`. On every engine start the first snapshot is **reconciled**: unfinished rows aria2 no longer knows are matched by URL + folder to an unknown live download (GID changed) or marked `interrupted`. (Measured with real aria2: GIDs *do* survive a graceful restart because the session file stores them.)
- **Session safety:** before each start `SessionFile.PrepareForStart` backs up a healthy `aria2.session` (skipping a copy identical to the newest, 5 kept in `backups\`), and replaces a damaged one (zero bytes or invalid UTF-8, what a power loss leaves) with the newest healthy backup, raising an `EngineNotice`.
- **Crash restart:** `Aria2Engine` still just reports `Crashed`; `EngineSupervisor` + `RestartPolicy` (1 s, 3 s, 10 s pauses, at most 3 restarts per 5 minutes) restart it, and `GaveUp` leaves the manual "Restart engine" bar. The error bar stays hidden while a restart is pending (`IsRecovering`).
- **Leftovers:** once per launch, after the first snapshot, `OrphanFiles.Find` looks for `*.aria2` files in History's folders and the Downloads folder that no live download owns. Entries whose History row is `removed` or `error` are ignored; the banner offers Resume (needs a known URL, uses `continue=true`) and Delete leftovers (confirmation first).
- **UI plumbing:** `NoticeCenter` is the one banner under the title bar (any thread can post; one at a time). `PersistenceCoordinator` wires recorder, notices, retention and the leftover scan. The History page queries on a background thread with a 250 ms debounce, newest request wins, and checks "file missing" afterwards.
- **Window position:** saved from `AppWindow.Changed` (only while restored, so a maximized or minimized window never overwrites it), fitted to today's monitors by `WindowPlacementFitter`, and applied again on first activation because Windows ignores a move made before the window is first shown. Gotcha: LINQ over `DisplayArea.FindAll()` throws a marshalling error; index it.
- Gotchas: an `x:Bind` `FallbackValue` cannot produce an enum (it throws at runtime on every start); `InfoBar.ActionButton` must be a button (use `InfoBar.Content` for several).

## Torrents (0.5)
Facts verified against the real aria2c 1.37.0 by `TorrentSpikeTests` (a second aria2c seeds on loopback, a local `HttpListener` tracker hands out its address; no DHT, no internet). The design relies on them.
- **Seeding is not a status.** A finished torrent with the default `seed-ratio=1.0` stays `status=active` with `seeder=true`; the app derives "Seeding" from that. `seed-time=0` (alone) makes aria2 end the download as `complete` right after the data is verified. Careful: `seed-ratio=0.0` means "seed forever", and `seed-ratio=0.0` with `seed-time=0` ends seeding at once.
- **Seeding does not survive a restart.** `save-session` keeps unfinished downloads only; a torrent whose data is complete (even while uploading) is not written, so after an engine or app restart it is gone from aria2 and seeding stops. An unfinished or paused torrent does come back with the same GID and hash. History therefore records Seeding as `complete` (with its finish time) instead of an "unfinished" row that the next start would mark interrupted. Resuming seeding means adding the torrent again with `check-integrity`.
- **History for torrents:** schema v2 adds `info_hash`, `is_torrent`, `uploaded_bytes`. Reconcile matches a torrent whose GID changed by info hash (it has no URL). A magnet's `[METADATA]` placeholder is never recorded and is hidden from the list once complete (`DownloadView.IsSuperseded`); the follower download is the torrent. A placeholder that fails stays visible.
- **Choosing files:** add with `pause=true`, change `select-file` (1-based, `"1,3-5"`) through `changeOption`, then `unpause`. Nothing is downloaded while paused, and afterwards `totalLength` shrinks to the selected files plus the pieces they share with neighbours (67,232 of 100,000 bytes when picking the 60,000-byte file of two).
- **Magnets:** `pause-metadata=true` completes the metadata GID and creates a *paused* follower listed in the metadata GID's `followedBy`; the follower has all files, so the file picker can show them and `select-file` can be set before `unpause`. The follower reports **no** `belongsTo`, so the link only runs forward (remember it from `followedBy`).
- **Metadata-only:** `bt-metadata-only=true` + `bt-save-metadata=true` ends `complete` with no follower and writes `<infohash>.torrent` into `dir`. Gotcha: aria2 saves it **only if `dir` already exists** (nothing is logged or raised otherwise), so create the folder first.
- **Recheck:** adding a torrent whose data is already in `dir` with `check-integrity=true` verifies and completes without downloading (`downloadSpeed=0`).
- **Engine config:** `Aria2Config.Render` now sets `bt-save-metadata`, `bt-load-saved-metadata`, DHT (v4 and v6, state kept in `engine\dht.dat`/`dht6.dat`), LPD, `seed-ratio=1.0` and `file-allocation=none` by default (falloc zero-fills the whole file without the volume-maintenance privilege). Saved `<infohash>.torrent` files therefore appear in the download folder, which is aria2's behaviour and cannot be redirected.
- **User settings (0.7):** `EngineOptions.ToGlobalOptions(AppSettings)` is the one mapping from settings to aria2 option names. `Aria2Engine` takes a `Func<AppSettings>` and re-reads it on every start (conf lines and `dir`); `SettingsApplier` pushes the same options with `changeGlobalOption` and owns the alternative-speed toggle (`SetAltSpeedAsync` flips `AltSpeedActive` and changes only the two `max-overall-*-limit` options). `max-concurrent-downloads` goes through `DownloadOperations.SetBaseConcurrentAsync` so force-start bookkeeping stays right. aria2 accepts but silently ignores some options in `changeGlobalOption` (checked against 1.37.0 with a real engine): `EngineOptions.LaunchOnlyKeys` lists them (`check-certificate`, `disable-ipv6`, `listen-port`, `dht-listen-port`, `enable-dht`, `enable-dht6`); `LiveOptions` leaves them out and `SettingsApplier.RestartRequired` compares them (plus the default folder) with what the engine started with to show the restart bar. Everything else, including peer exchange, LPD, encryption, `seed-ratio`, `seed-time` (an empty value clears it) and `bt-tracker`, applies live. Torrent seeding options are per-download, so they only reach torrents added afterwards; the per-torrent `Forever` and `Ratio` choices also send a ten-year `seed-time` so a global time limit cannot end them early. Empty option values are left out of the conf file (they mean "not set").
- **Add options (0.7):** the Add dialog's "More options" build an `AddOptions` (headers, referer, cookie, login, checksum, per-download limits). It validates everything (no control characters, so no header injection), maps to aria2 option names with `ToOptions()`, never prints its secrets, and is not persisted. It is merged into plain URL adds, torrent files (`TorrentAddRequest.Extra`), metalinks, and magnets (applied when the metadata is resolved, so credentials are not used for the metadata fetch). `header` is repeatable, so `Aria2RpcClient` turns a `header` value with one header per line into a JSON array. aria2 only sends a login after a 401 challenge, and keeps per-download options (including `http-passwd`) in its session file while a download is unfinished. "Site presets" (`HeaderPresets`, `presets.json`) store headers, referer and a DPAPI-protected cookie.
- **General (0.7):** the theme is applied by setting `RequestedTheme` on the main window's root element (`App.ApplyTheme`), at launch and live from Settings; dialogs follow. The name-clash policy (`ConflictPolicy`: keep both, replace, ask) is sent to aria2 as `allow-overwrite` / `auto-file-renaming` for new downloads, and `DownloadsViewModel.AddAsync` also checks plain links before adding them: `FileConflicts.FindExisting` guesses the target from the typed name or the end of the link (a server-chosen name is unknown beforehand) and ignores files with an `.aria2` control file, which are resumes. Each choice adds `continue=false`, because with the engine's `continue=true` aria2 would otherwise resume the old file instead of renaming or replacing it. `LICENSE.txt` and `THIRD-PARTY-NOTICES.md` ship next to the exe and are shown from the About page.
- **Advanced (0.7):** hand-typed aria2 options (`AppSettings.RawOptions`, edited as `name=value` lines) are merged last in `EngineOptions.ToGlobalOptions`, so they override the settings pages. `RawOptionRules` is a security boundary: lowercase option names only, and everything the app owns, that can run a program (`on-*`), write arbitrary files, or carries a login is refused; control characters are refused everywhere because values end up in the conf file (`Aria2Config.Render` also drops any line with one). Raw options are sent one by one after the other settings so a refused option cannot block the rest (aria2 refuses unparsable values but silently accepts names it does not know, so a misspelled name is not reported), and any change suggests an engine restart (there is no way to know which are launch-only). `SettingsTransfer` exports without machine state (window, last folder, proxy password), imports with validation (refuses unknown choices, bad proxy/tracker addresses, forbidden raw options, control characters; clamps numbers; keeps this PC's machine state) and implements "Reset all". The log level is one setting for both logs (`FileLoggerProvider.MinLevel` changes at runtime; aria2's `log-level` applies live). The Settings page groups its controls into one panel per header marked `Tag="section"` at runtime (`BuildSections`), which is what the search box and the jump list work on.
- **Localization (0.7):** UI text lives in `Aria2NET\Strings\en-US\Resources.resw`. XAML elements get an `x:Uid` and keep their English attribute as a default (the resource overrides it when it loads, and English still shows if a lookup ever fails); keys look like `SettingsPage_ThemeBox.Header`. Code uses `Loc.S("Key", "English")` and `Loc.F("Key", "English {0}", args)`, which also fall back to the English text. `LocalizationTests` keeps XAML defaults, `Loc` calls and the .resw identical and checks `x:Uid`s, keys and format placeholders. `Aria2NET.Core` stays free of UI resources: text it produces for the user (toast bodies, `Aria2Errors.Describe`, `ByteFormat`, `WhenFinishedMachine.Label`, validator messages in `EngineOptions`) is English-only until Core returns keys or typed reasons. A second language means adding `Strings\<culture>\Resources.resw` and a language choice in Settings (the box is a fixed "English" for now). Attached properties use the long resw form, for example `[using:Microsoft.UI.Xaml.Automation]AutomationProperties.Name`.
- **Public trackers:** `TrackerListService` caches a list (default: ngosang/trackerslist `trackers_best.txt`) in `trackers.txt`. The engine only reads the cache at start (`bt-tracker`), so a dead network never delays startup; the app refreshes a week-old cache after the engine is up and applies it with `changeGlobalOption`. The list ends up in the conf file, so `Parse` rejects any line with whitespace, control characters or a comma and keeps only http/https/udp, at most 40.
- **Free space:** `DiskSpace.FreeBytes` (`GetDiskFreeSpaceExW`, works for network shares, walks up to the nearest existing parent) and `Fits`, which never blocks when the space is unknown.
- **Adding (Core `TorrentOperations`):** a `.torrent` is parsed first (`TorrentMetadata`, info hash = SHA-1 of the raw `info` bytes, never of a re-encoded copy), the file picker shows its files, then it is added with `dir`, `select-file`, seeding and allocation options in one `addTorrent` call. A magnet is added with `pause-metadata=true` and `dir` (created first); `WaitForMetadataAsync` follows it to the paused follower, the picker shows the follower's files, `StartAsync` sets `select-file`/seeding/allocation with `changeOption` and unpauses. `dir` cannot be changed on an existing download (aria2 ignores it), so a magnet's folder is the one from the Add dialog. Metalinks go through `addMetalink` (one download per file).
- **List behaviour:** the finished metadata placeholder is dropped from the list in `DownloadsViewModel.Apply` and never recorded; `CheckDiskSpace` warns once per download when its size becomes known and does not fit; duplicate torrents (same info hash, running now) are refused with a notice, ones only in History get a note in the picker.
- **Seeding rules:** per torrent only, as `seed-ratio`/`seed-time` (`SeedingOverride`); changing them on a running torrent works (`changeOption`). **Check files again** pauses, sets `check-integrity=true`, unpauses; aria2 re-verifies and refetches damaged pieces (tested by corrupting a file).
- **Details window:** `TorrentDetailLoader` reads `tellStatus`, `getFiles` and `getPeers` once a second while the window is open. aria2 reports no tracker status or messages and cannot change the trackers of an added torrent (checked), so the Trackers tab is a read-only list. The piece bars come from the `bitfield` of the torrent and of each peer. Peer clients come from the peer id (`PeerIdClient`); countries from an optional DB-IP Lite CSV (`tools/get-geoip.ps1`, loaded in the background, never sent anywhere) shown as a two-letter code, because Windows does not render flag emoji.
- **Opened from outside:** `Program.cs` collects `.torrent`/`.metalink`/`.meta4` paths and `magnet:` links from the command line of the first launch and from the arguments of a redirected second launch (`LaunchArguments`, Launch/File/Protocol activation), and `App.HandleExternalLaunch` opens the Add dialog with them. `ShellRegistration` writes only under HKCU (ProgIds, `OpenWithProgids`, Capabilities, `RegisteredApplications`), never changes anyone's default, and reports whether the user picked Aria2NET (`UserChoice`). Settings > Torrents has the toggle; the Downloads page offers it once (`TorrentAssociationPrompted`).
- **Not available from aria2:** DHT node count and port reachability (the footer shows upload speed and peers instead), tracker status, global seeding statistics.
- **Orphan cleanup:** `Aria2Engine.KillOrphans` kills every `aria2c` running from the engine's exe path, so tests start the seeder from a copy of `aria2c.exe`.

## Single instance
`Program.cs` (custom `Main`, `DISABLE_XAML_GENERATED_MAIN`) registers an `AppInstance` key. A second launch redirects to the first, which brings its window to the front.

## Data locations
- `%LocalAppData%\Aria2NET\settings.json`, `logs\`, `engine\` (conf, session).
- aria2 itself: `<app folder>\tools\aria2\aria2c.exe`.

## Why unpackaged
No MSIX means no registry/file virtualization, easy native messaging for the browser extension (2.0), easy launching of bundled tools, and a Velopack installer (0.8) with a portable zip as the alternative.

## Getting started
```
pwsh -ExecutionPolicy Bypass -File tools/get-aria2.ps1
dotnet build Aria2NET.slnx -p:Platform=x64
dotnet test Aria2NET.Tests
dotnet run --project Aria2NET -p:Platform=x64
```
`tools/aria2/` is git-ignored. The script pins aria2 1.37.0 and verifies a SHA-256.
